# Use SQLite (stdlib, no ORM) as the local persistence mechanism

We need local persistence for Task, Tag, and Pomodoro history that supports day/month calendar queries, active-vs-archived Tasks, a many-to-many Task↔Tag relation, and no network or external service — while keeping unit tests fast and free of a real database (deterministic-gate constraint). We chose SQLite via Python's stdlib `sqlite3`, with no ORM: it gives relational joins and date-range queries natively, and a many-to-many relation (`task_tags`, with `ON DELETE CASCADE` and `PRAGMA foreign_keys = ON`) without hand-rolled cascade/filter logic in Python. A JSON-file store was rejected because it would push joins, cascades, and date filtering into application code; an ORM (e.g. SQLAlchemy) was rejected as an unnecessary dependency and abstraction layer for a schema this small, especially under the file-size-guard/complexipy/deptry gates. The data directory is resolved via `platformdirs` rather than hand-rolled XDG paths, to cover both target OSes (Linux, Mac) correctly.

Unit tests use a fresh `:memory:` SQLite connection per test (fast, no filesystem I/O); a real temp-file (`tmp_path`) is reserved for integration tests that specifically exercise the on-disk path. No formal schema-migration mechanism exists yet (`CREATE TABLE IF NOT EXISTS` only) since there's no released user data to migrate — revisit if a breaking schema change is needed post-release.

## Considered and rejected

- **Persisting the live timer/break state** (to resume across app restarts): rejected — the timer/session spec (issue #4) has no requirement to resume, and it would add a "current session" table plus recovery logic (crash mid-Pomodoro, clock changes) for no requested benefit. Only finished Pomodoros (`completed` or `interrupted_logged`) are persisted; interrupted-and-discarded Pomodoros are never written.
- **A stored counter for completed-Pomodoro cadence** (the every-5th-break rule from issue #4): rejected in favor of deriving it with `COUNT(*) WHERE status='completed'` on demand, avoiding a second source of truth to keep in sync.
- **A derived `date` column on `pomodoro`** for calendar queries: rejected in favor of `strftime()` over `started_at` directly at query time — at this scale the extra column isn't worth the sync risk.
