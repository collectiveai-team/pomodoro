# Use PySide6/Qt6 as the desktop GUI framework

We need a Linux+Mac desktop GUI framework for Python 3.14. We considered PySide6/Qt6, Tkinter (stdlib), and Kivy. Kivy's stable release (2.3.1) only supports Python up to 3.13 and fails to install on 3.14, with no released fix. Between PySide6 and Tkinter, we chose PySide6: it ships built-in rich widgets we need out of the box (`QCalendarWidget` for the history/calendar view, `QSoundEffect` for the alarm), gives a native-per-OS look by default, and its LGPLv3 license (dynamic-linking obligation) is acceptable since there's no plan to distribute a closed-source build. Tkinter would have avoided the extra dependency and packaging weight, but would have required third-party libraries (`tkcalendar`, `playsound`/`simpleaudio`) to reach the same functionality, and its widgets look dated without significant theming investment. Packaged app size (PySide6 pulls in unused Qt libs unless trimmed with `--exclude-module`) is accepted as a cost since native packaging/distribution is out of scope for now.

Qt's bootstrap (`QApplication`, main window, event loop, signal wiring) lives entirely in the `entrypoints` layer (CES-5 layer direction: `entrypoints -> api -> database|impl -> core`), calling only into the `api` layer — no domain logic in views.
