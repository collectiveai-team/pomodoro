# Module layout and the core/GUI seam

We need a concrete package layout inside `pomodoro` and a seam between domain logic and the GUI, so `core` is 100% unit-testable with no GUI, network, or real DB. We chose four layers, strictly one-directional and non-skippable — `entrypoints -> api -> database -> core`: `api` is the sole inbound boundary (CES-17), so `entrypoints` never imports `core` or `database` directly, even for reads. `core` holds the Task/Tag/Pomodoro entities and their rules, the session/timer state machine (plus Break), the `filter_tasks` contract, and the History rule (completed + interrupted-logged Pomodoros count); it also declares the Protocol interfaces it needs (`TaskRepository`, `TagRepository`, `PomodoroRepository` in `repositories.py`) and an abstract clock/tick interface plus a plain Qt-free observer/callback mechanism (both in `timer.py`) — core depends on these abstractly and never imports `sqlite3` or Qt. `database` implements those Protocols against SQLite as a single layer (the "database | impl" wording in the earlier `pyproject.toml` comment was two names for one layer, not two sub-layers). `api` stays named `api` despite there being no HTTP, for consistency with the layer-naming convention already fixed in `pyproject.toml` (CES-5/CES-17); it's a thin use-case layer (`tasks.py`, `tags.py`, `session.py`, `history.py`) that wires `core` and `database` together for `entrypoints` to call. `entrypoints` is the only layer allowed to import Qt/PySide6: `app.py` bootstraps `QApplication` and wires dependencies, `signals.py` adapts core's plain observer callbacks into Qt signals, and the real `QTimer` driving core's abstract tick interface also lives here; concrete widgets/views live under `entrypoints/qt/`.

The `[tool.importlinter]` skeleton in `pyproject.toml` is updated to this concrete layout: a `layers` contract for `entrypoints -> api -> database -> core`, plus the pre-existing CES-17 "API is the only inbound boundary" contract adjusted to also forbid `entrypoints` from importing `core`/`database` directly (the `layers` contract alone doesn't forbid skipping a middle layer).
